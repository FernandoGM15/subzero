## Specs

- S1 — User: “Vale si dejemoslo como FieldConntainer y documenta ese subfijo para futuros desarrollos”. Approved spelling: FieldContainer. Use content projection for border, label, required marker, help/error and message spacing; controls retain native elements, model, focus/events and forms. Preserve all existing Input behavior and public inputs/outputs.
- S2 — User: “Listo entonces preseguimos con el desrrrollo del select?” and final implementation approval “sip”. Approved contract (revised by S6): single-select with consumer-supplied readonly option records `{ value: string | number | null, label: string, disabled?: boolean }`; unique values, preserving primitive type including `0`, `''`, and numeric/string lookalikes. Null alone means empty; never automatically select the first option. A consumer-supplied null option permits clearing even when required; without it no visible empty choice is generated.
- S3 — Approved interview contract: retain a selected value when its option disappears and display an unavailable-option indicator. Floating label rests only when null and unfocused; a consumer null-option label must not overlap it; remove placeholder input. Standalone `[(value)]` or Signal Forms `[formField]`, one per instance; programmatic focus and blur/touch. External error replaces helper; one reserved message line by default with opt-out; shared CONTROL sizes and subtle focus.
- S4 — User accepted “No options available” with “Oeky” and excluding readonly/using disabled with “vale si”. Disabled control and per-option disabled states; no HTTP, editable search, multi-select, virtualization, or readonly in this version. Document readonly Signal Forms limitation.
- S5 — User confirmed: “El alcance queda definido. Implementaremos primero FieldContainer, preservando el comportamiento de Input; después, Select con el contrato acordado, pruebas y documentación.” → “sip”. Define contracts in docs/ui-kit.md before source implementation; update roadmap after observed checks.

- S6 — User: “Me parece bien la implementación propia”. Proposal: “¿Autorizas incorporar @angular/aria y @angular/cdk?” → user “okey”. Replace native panel with custom Tailwind presentation using Angular Aria keyboard/focus/semantics and CDK Overlay positioning; no Material. Preserve S1-S5 consumer API except native DOM implementation: one selection, string/number/null identity, consumer-owned null choice, external errors, sizing and Signal Forms. Required checks: click/keyboard open, navigation skips disabled, commit, Escape/outside/Tab close, no unintended value emission, focus/touch semantics, option updates, overlay alignment configuration and accessible labels. Style panel with existing semantic surface/border/radius tokens and bounded scroll, no new theme API.
- S7 — User: “Veo que el select de shadcn tiene un width mas amplio que el que el texto necesita, me gustaría algo asi porque si el texto de la label es muy pequeño el select igual queda raro” → “verifica lo del width” → “sip”. Set a 180px base width adjustable by the consuming instance; cap it at 100% of its container. Document and test both default and consumer override.
- S8 — User: “Al hacer hover sobre la label el cursor es text, me gustarpia que fuera pointer en todo el select”. Use pointer cursor across the complete enabled Select including its label; preserve a not-allowed cursor when disabled. Keep Input's text cursor unchanged.
- S9 — The hover option and keyboard-active option use the same background highlight.
- S10 — User: “dejalo como estaba, creo que se ve mejor que el contorno”. Revert the ring proposal and retain the same background highlight for pointer hover and keyboard-active options.
